# 8 張參考圖精準對齊 UI 規格

## 1. 驗收基準

本次 UI 重構只以使用者確認的 8 張圖片為視覺驗收標準。不得再沿用先前的深綠大焦點卡、大片漸層或自行發明新的資訊架構。

4. `/Users/kcjiang/Downloads/產生的圖片 4.png`：待辦

桌機參考：

2. `/Users/kcjiang/Downloads/產生的圖片 2 (1).png`：預訂

4. `/Users/kcjiang/Downloads/產生的圖片 4 (1).png`：待辦

「精準對齊」指結構、資訊優先順序、色彩角色、卡片比例、導覽位置及主要操作位置必須一致。示意圖中的京都名稱、金額、日期與人物不是固定資料；實際畫面仍使用 app 中現有資料。

## 2. 不可偏離的共用設計

- 全頁使用暖白紙張感背景，卡片為白色或微暖白，細灰米色邊線與輕柔陰影。
- 主文字為深藍墨色，輔助主色為霧藍，狀態與自然資訊使用灰綠，唯一高強調操作色為珊瑚橘。
- 標題使用具編輯感的明體／宋體系統字；內文、數字與控制項使用清楚的無襯線字。
- 所有主要卡片使用一致圓角、邊線、陰影與內距；手機約 16–22px 圓角，桌機約 12–16px。
- 手機固定四項底部導覽：行程、預訂、待辦、記帳。選取項同時以色彩、上方短線及圖示／文字表達。
- 桌機固定左側導覽，內容區依參考圖使用主欄加右側摘要欄；不把手機卡片單純放大。
- 手機主內容寬度為單欄，390px 不得出現橫向捲動；桌機以 1440px 為主要驗收尺寸。
- 所有既有資料、對話框、PDF、雲端同步、匯入匯出、唯讀模式及票券附件功能保持可用。
- 不讀寫或覆蓋使用者既有 localStorage／雲端資料；截圖驗證使用隔離瀏覽器 context 與專用示範資料。

## 3. 手機行程頁

參考：`產生的圖片 1 (1).png`

不可偏離元素：

- 頂部為返回、置中旅程名稱、右側漢堡／更多；不顯示舊版副標題或深綠焦點區。
- Day 切換是三等分 segmented control，選取日為霧藍填滿並有下方短線。
- 下一列左側為 `Day N・日期` 大標，右側為獨立天氣膠囊。
- 全部行程直接呈現在同一條垂直時間軸，不獨立放一張「下一個行程」深色焦點卡。
- 每筆卡片左側呈現時間與名稱、地點／時長，右側有 1:1～4:3 圖片與箭頭；左側軸線使用圓形類型圖示。
- 珊瑚橘圓形新增按鈕浮在右下、底部導覽上方。
- 首屏資訊順序固定為：頂部 → Day 切換 → 日期／天氣 → 時間軸卡片 → 浮動新增。

## 4. 手機預訂頁

參考：`產生的圖片 2.png`

不可偏離元素：

- 頂部只有置中「預訂」與右側篩選圖示。
- 分類膠囊順序為：全部、票券、交通、住宿、餐廳；單列橫向滑動，選取項霧藍填滿。
- 第一張為珊瑚描邊的下一筆票券焦點卡，必須顯示今天／時間、名稱、QR 視覺區及珊瑚色「開啟票券」。
- 下方一般預訂卡為單欄列表；左側類型圖示，中間名稱／日期／地點，右側確認狀態與箭頭。
- 一般卡片不使用大封面圖，不呈現舊版大面積深綠／深藍背景。

## 5. 手機記帳頁

參考：`產生的圖片 3.png`

不可偏離元素：

- 頁首左側大標「記帳」，右側為參與者頭像列。
- 第一張摘要卡左側為總支出與參與人數，右側為甜甜圈圖及分類百分比。
- 摘要卡後立刻是全寬珊瑚色「＋ 新增支出」。
- 明細按日期分組；每筆包含分類圖示、名稱、付款人頭像與名稱、右側金額與箭頭。
- 結算建議以獨立卡呈現，醒目顯示「你應支付給誰」與珊瑚色金額。
- 成員、匯率與進階統計不得占據手機第一屏，移到後段或可收合設定。

## 6. 手機待辦頁

參考：`產生的圖片 4.png`

不可偏離元素：

- 頁首為大標「待辦」、完成數字，右上可有行李插畫／簡化旅行圖形但不能壓縮文字。
- 分類膠囊順序：行前準備、行李打包、購物清單、旅途中提醒；單列橫向滑動。
- 第一張為完成進度卡：大數字 `完成 / 全部` 與環形進度。
- 清單按「今天要完成」與「可選」等狀態分組。
- 每列為獨立白色卡片：左側大圓勾選、中間待辦文字、右側時間或負責人膠囊與箭頭。
- 最後為全寬珊瑚色「＋ 新增待辦」。

## 7. 桌機行程頁

參考：`產生的圖片 1 (2).png`

不可偏離元素：

- 左側固定導覽；上方品牌圖章；行程總覽為選取狀態；設定置底。
- 內容頂端是旅程標題與日期，右側有收藏／分享／更多。
- 標題下方顯示旅程路線摘要，再進入主欄 Day segmented control。

參考：`產生的圖片 4 (1).png`

## 11. 響應式與功能保留

- `<= 679px`：手機結構，固定底部導覽、單欄內容、隱藏桌機側欄。
- `680–1099px`：維持手機資訊順序，可增加內容寬度；不硬塞桌機雙欄。
- `>= 1100px`：桌機固定側欄，主欄與右側摘要欄；底部導覽轉為側欄，不重複顯示。
- 頁面切換仍使用現有 `data-trip-section` 狀態；新增、編輯、票券、附件、勾選、支出與 PDF 事件必須沿用原功能。
- 圖片缺失時使用低干擾的類型占位，而不是破圖；示範截圖可使用隔離資料中的圖片 URL。
- 長旅程名、地址、票號與金額不可撐破卡片。

## 12. 驗收與回退

- 每個新增純函式 helper 先寫測試並確認 RED，再寫最小實作至 GREEN。
- 每完成 layout foundations、itinerary、bookings、expenses、todos 其中一階段，執行完整 Node 測試與 `node --check app.js`，通過才 commit。
- 四頁都要各產出 390px 與 1440px 截圖，共 8 張。
- 每張截圖以 `view_image` 人工檢查：資訊順序、卡片比例、導覽、選取狀態、按鈕與參考圖的差異。
- Chrome console 不得出現新的 JavaScript error。
- 不修改、搬移或清除使用者未追蹤檔案；所有重構都留在 `codex/mobile-first-ui`，可依 commit 分段回退。

## 13. 規格自我檢查

- 無 TODO、TBD 或未決視覺方向；8 張圖片就是唯一樣式答案。
- 手機與桌機皆有逐頁結構，不以「自動放大」代替桌機設計。
- 所有既有功能與資料都明確列入保留範圍；驗證資料明確要求隔離。
- 本規格不新增地圖、付款、通知或第三方服務，範圍只限 UI 與必要的渲染結構。
