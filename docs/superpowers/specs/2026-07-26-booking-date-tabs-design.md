# 預訂與票券日期小分頁設計

## 目的

讓「預訂與票券」不再把同一分類的所有預訂卡片擠在同一頁。使用者先選分類，再選該分類實際有預訂的日期，只看當天的卡片。

## 範圍與不變項目

### 會新增的畫面行為

- 保留第一層分類分頁：`全部`、`票券`、`交通`、`住宿`、`餐廳`。
- 在第一層分頁下新增第二層日期分頁。
- 日期分頁只列出目前分類、目前使用者有權查看、且實際有預訂的日期。
- 選日期後，主清單只顯示該日期、該分類的預訂卡片。

### 明確不做的事

- 不修改 `booking` 物件、資料庫欄位、Supabase 同步、私人／共享權限或現有分類值。
- 不重新分類既有預訂，也不變更「票券、交通、住宿、餐廳」的既有篩選規則。
- 不改動右側／下方的「即將到來的預訂」與「預訂檢查清單」摘要範圍；這次只改主預訂清單的瀏覽方式。
- 不把多日住宿複製成多筆資料或多張日期卡片。

## 介面與互動

### 雙層分頁

1. 第一層維持目前的分類分頁與圖示。
2. 第二層放在第一層下方、預訂卡片清單上方，採可水平捲動的小分頁，避免手機窄螢幕擠壓。
3. 每個日期顯示 `M/D（週X）`，例如 `7/1（週三）`；日期由早到晚排列。
4. 目前選取的日期使用與目前分類一致的啟用樣式；其他日期維持可辨識的未選取樣式。

### 選取規則

- 初次進入預訂頁，先套用目前分類；日期預設為該分類最早的一個有預訂日期。
- 使用者切換第一層分類時，立即重新計算可選日期，並一律選取新分類最早的一個日期。
- 使用者只切換第二層日期時，第一層分類不變。
- 同一個分類因畫面重繪而再次呈現時，若原選日期仍存在則保留；若已不存在，改選最早日期。
- `全部` 也採相同規則：列出所有可見預訂合併後實際有預訂的日期，不列出沒有任何預訂的旅程日期。

## 日期歸類規則

1. 先以既有的分類規則篩出可見預訂：`全部` 不限分類；其他分類沿用 `getBookingGroup` 的結果。
2. 再以既有的排程日期規則取得每筆預訂的日期：交通使用出發日（若無出發日才使用預訂日）；其他類型使用預訂日。
3. 每個有效 `YYYY-MM-DD` 日期只產生一個日期分頁，不因同日有多筆預訂而重複。
4. 日期以 ISO 日期字串升冪排序，顯示時以台灣時區轉為 `M/D（週X）`。
5. 住宿一律以入住日（`booking.date`）歸類；即使有退房日，也不可在退房日或住期間的其他日重複出現。

## 資料流與狀態

主清單使用下列純畫面資料流，資料來源永遠是既有、已過權限篩選的 `trip.bookings`：

```text
可查看的預訂
  → 依 activeBookingGroup 篩選
  → 依既有排程日期取值
  → 取不重複且排序後的 availableBookingDates
  → 依 activeBookingDate 篩選
  → 渲染日期分頁與當日預訂卡片
```

新增的暫時介面狀態為 `activeBookingDate`：

- 值為目前選取的 `YYYY-MM-DD`，沒有可選日期時為空值。
- 它只代表瀏覽器此刻的畫面選擇，不寫入 `booking`、旅程資料、雲端資料或權限資料。
- 分類切換時由可選日期的第一筆重設；同一分類重繪時僅在日期仍有效時保留。

建議把「分類篩選」、「可用日期計算」與「日期篩選」做成可單獨測試的純函式，讓卡片清單和日期分頁共用同一份結果，避免頁籤顯示與卡片內容不一致。

## 邊界處理

| 情況 | 顯示與行為 |
| --- | --- |
| 該分類沒有任何可查看預訂 | 不顯示第二層日期分頁，主清單顯示目前的分類空狀態。 |
| 該分類有預訂，但全都沒有有效排程日期 | 不顯示第二層日期分頁；主清單以「日期未定」獨立區塊列出這些卡片，不能讓既有資料消失。 |
| 有已排程預訂也有日期未定預訂 | 日期分頁只列有效日期；選日期時主清單只顯示該日卡片。日期未定卡片以清楚的「日期未定」獨立區塊置於日期清單後方，不混入任何日期分頁。 |
| 目前選取日期因編輯、刪除或權限變化而消失 | 重新計算後自動選最早可用日期；若已無日期，清空 `activeBookingDate` 並顯示相應空狀態。 |
| 同日多筆不同分類預訂 | 在 `全部` 的該日期一次顯示；在個別分類只顯示屬於該分類的卡片。 |
| 多日住宿 | 僅出現在入住日的日期分頁一次；不因退房日重複。 |
| 交通有出發日與一般預訂日不同 | 依現有規則以出發日歸類，與既有卡片時間線一致。 |

## 驗收條件

1. 選「交通」後，日期小分頁只包含有交通預訂的日期，且由早到晚排列。
2. 選「全部」後，日期小分頁只包含任一可查看預訂存在的日期，不顯示空白旅程日期。
3. 點選任一日期後，卡片清單只顯示該日、該分類的預訂。
4. 切換分類後，日期自動回到新分類最早的有資料日期。
5. 該分類沒有可查看預訂時，不出現日期小分頁，且有清楚空狀態。
6. 住宿跨多日仍只在入住日出現一次。
7. 日期未定的既有預訂不會因新分頁而消失，並能和有日期的預訂清楚區分。
8. 手機寬度下兩層分頁都可橫向捲動、文字不折行；桌面寬度下可清楚辨識選取狀態。
9. 新增、編輯、刪除預訂及同步重新渲染後，日期分頁與卡片內容保持一致。
10. 現有私人票券與預訂可見性規則不變；日期分頁不洩漏使用者無權查看的日期或預訂。

## 測試策略

### 單元測試

- 分類為 `全部` 時，從所有可查看預訂產生不重複、升冪的日期。
- 個別分類只產生該分類的日期。
- 交通使用出發日；住宿只使用入住日；同日多筆僅產生一個分頁。
- 選取分類或日期後，回傳的卡片集合正確。
- 無日期、分類無資料、選取日期被刪除等邊界能回傳明確狀態。

### 介面檢查

- 使用含多日、多分類、同日多筆、跨日住宿與未定日期的驗收資料，在手機與桌面尺寸檢查。
- 逐一切換五個分類與其日期分頁，確認日期排序、卡片篩選、空狀態及住宿只出現一次。
- 以不同旅伴登入或模擬可見性後，確認日期分頁只來自可查看預訂。

### 回歸檢查

- 新增／編輯／刪除預訂後重算日期分頁。
- 既有預訂卡片、電子票券、附件、摘要及同步流程仍可正常使用。

## PWA 發布策略

- 此功能會改動 HTML、JavaScript 與 CSS 時，三者查詢版本號需一起遞增。
- Service Worker 的快取名稱與預快取資產版本同步遞增，包含新增或改版的純函式模組。
- 發布後以正式 GitHub Pages 檢查 Service Worker 已取得新快取版本，再以手機與桌面重新載入驗證雙層分頁。
- 不使用強制覆蓋推送；先在功能分支完成測試與畫面檢查，再合併至 `main` 發布。
