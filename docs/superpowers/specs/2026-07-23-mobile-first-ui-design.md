# 手機優先 UI 設計規格

## 1. 目標

讓「旅．拾光」在旅行途中用手機也能快速看懂、單手操作，並保留既有暖白紙張、墨綠與旅行手帳的質感。這不是把電腦畫面縮小，而是先把手機當成主要畫面，再讓平板與桌機有更多空間時自然展開。

使用者進入一趟旅程後，最常完成的四件事是：看今天行程、找票券或預訂、勾待辦、記一筆支出。介面必須把這四件事放在最容易碰到的位置；較少使用的 PDF 預覽、旅程編輯、成員與匯率設定，則放在不干擾主要流程的位置。

## 2. 目前範圍與現況

本規格只調整介面排版、視覺層級與操作順序，不改變既有資料、同步方式或功能規則。

目前 `index.html` 已有一個旅程頁面，包含：

- 上方標題列：返回旅程清單、頁名、編輯旅程。
- 日期切換列：目前日、前後日與每日名稱。
- 主要功能頁籤：總覽、預訂、PDF 預覽、待辦、記帳，以及中央新增按鈕。
- 總覽內已有天氣、當日旅程、今日票券、時間軸與新增行程。
- 預訂、待辦、記帳各自已有分類頁籤與完整資料內容。

目前 CSS 已是窄版優先：內容寬度最高 780px、底部功能列固定、360～460px 時會改成單欄。這次的工作是把這個基礎收斂為一致的手機設計系統，而不是重新做一個 app。

## 3. 手機資訊架構

### 3.1 固定區域

由上到下固定採用三層：

1. **頂部列**：返回、目前頁名、編輯或更多操作。高度保持 56px 左右，不放長段文字。
2. **日期列**：只顯示「前一天／今天／後一天」三個日期，中央永遠是目前選擇的日期；可左右滑動或用兩側箭頭換日。
3. **底部主導覽**：固定四個文字加圖示入口：行程、預訂、待辦、記帳。中央凸出的「＋」是新增資料入口；按目前頁面決定新增行程、預訂、待辦或支出。

PDF 預覽不再佔用底部主導覽的一格，改放在頂部「更多」選單或旅程編輯內的工具區。這能避免手機底部一次塞六個項目、文字過小而難按。

### 3.2 畫面內容順序

每個主頁只用單欄直向閱讀，依「現在最重要 → 需要操作 → 全部細節」排序。卡片之間保留固定間距；同一畫面只保留一個醒目的主要按鈕，其他操作改成文字按鈕、卡片右上角更多選單，或進入詳細頁後處理。

## 4. 各頁布局與互動

### 4.1 行程（預設首頁）

1. 日期列下方先顯示「Day X、城市／當日標題」與簡短狀態，例如「今天還有 3 個行程」。
2. 接著是可收合的天氣摘要卡；預設只顯示城市、天氣圖示、溫度與一行穿著提醒，點開才顯示分時天氣與搜尋城市。
3. 再顯示「現在／下一個行程」焦點卡。內容只保留時間、地點、預估停留時間與導航／查看票券；已結束行程縮成一般時間軸項目。
4. 今日有交通或票券時，顯示一張「下一張要用的票券」卡。按下即開啟票券、QR Code 或附件；其餘票券可由「查看全部」進預訂頁。
5. 最後是垂直時間軸。每筆行程至少有 48px 可點擊區域，點擊整張卡可展開或編輯；照片、備註與詳細介紹預設收合。
6. 「新增行程」固定在時間軸底部，另可由底部中央「＋」開啟；兩個入口功能相同，避免找不到新增位置。

### 4.2 預訂

1. 頁首先放「下一個預訂」焦點卡，依時間排序。交通／票券優先顯示出發時間、地點、訂位代碼和開啟票券按鈕；住宿顯示入住日期與地址。
2. 下方以可橫向滑動的分類膠囊切換：票券、交通、餐廳、住宿。選項不得換行或擠成兩列。
3. 每張預訂卡用單欄：類型標籤、名稱、最重要時間地點、一行狀態。封面圖片只在有圖片時顯示為 16:9 橫幅，避免窄螢幕的雙欄擠壓。
4. 點卡片開啟詳細資料；「開啟票券／查看附件」是卡片內唯一主要按鈕。編輯、刪除收進更多選單，避免旅行途中誤刪。

### 4.3 待辦

1. 頁首顯示整體進度，例如「12 / 18 已完成」，並用進度條輔助理解；不以顏色作為唯一狀態。
2. 分類切換採橫向滑動膠囊：行前準備、行李打包、購物清單、旅途中提醒。
3. 每列待辦左側為至少 24px 的勾選框，中央是待辦文字，右側只顯示必要的到期日、數量或金額。完成後文字可淡化並移到「已完成」收合區，但不自動消失。
4. 觸控列可直接勾選；點文字進入編輯。新增待辦由中央「＋」或列表底部「新增待辦」開啟。

### 4.4 記帳

1. 頁首先顯示「本趟已花／今日已花／待結算」三個摘要數字；金額須同時保留原幣與台幣換算，避免旅行中判斷錯誤。
2. 最上方主要操作是「新增支出」，由底部中央「＋」直接打開；表單先顯示金額、幣別、分類、付款人與分攤對象，其他備註放在後面。
3. 每日明細以日期分組，預設開啟今天；其餘日期可橫向切換或收合。每筆只顯示分類、名稱、付款人與金額，點擊才看分攤與備註。
4. 成員、匯率、完整統計與帳務總表屬於較少使用的設定，移到「設定與結算」收合區，預設不搶占第一屏。

## 5. 視覺系統（色彩與間距 token）

Token 是一組可重複使用的固定數值。實作時應集中在 CSS 最上方，之後全站共用，避免每張卡片各自調整而變亂。

| 類別 | 名稱 | 建議值 | 用途 |
| --- | --- | --- | --- |
| 背景 | `--color-bg` | `#F7F4EF` | 全頁暖白底 |
| 卡片 | `--color-surface` | `#FFFDF8` | 卡片與底部導覽 |
| 主文字 | `--color-ink` | `#182521` | 標題與重要文字 |
| 次文字 | `--color-muted` | `#66706B` | 說明、時間與次要資料 |
| 主色 | `--color-primary` | `#0F6B5F` | 選取狀態、主要按鈕 |
| 深主色 | `--color-primary-strong` | `#0A423C` | 標題、重點文字 |
| 強調色 | `--color-accent` | `#D98145` | 提醒或單一重點，不大量鋪底 |
| 資訊色 | `--color-sky` | `#DCEBF4` | 天氣等低優先資訊 |
| 錯誤色 | `--color-danger` | `#B42318` | 刪除與錯誤，必須搭配文字 |
| 邊線 | `--color-line` | `#D8DDD3` | 卡片分隔與輸入框 |
| 間距 | `--space-1/2/3/4/5/6` | `4/8/12/16/24/32px` | 所有內外距只使用這六種 |
| 圓角 | `--radius-card` | `12px` | 卡片、輸入框、次要按鈕 |
| 圓角 | `--radius-pill` | `999px` | 標籤、分類膠囊 |
| 陰影 | `--shadow-card` | `0 8px 24px rgba(24,37,33,.08)` | 僅卡片使用，避免每層都有陰影 |

字級採三層即可：頁面標題 24～28px、卡片標題 17～20px、內文 14～16px。內文不可小於 14px；按鈕及重要操作文字建議至少 15px。

## 6. 響應式策略

| 螢幕寬度 | 目標裝置 | 布局規則 |
| --- | --- | --- |
| 320～459px | 一般手機 | 單欄；左右內容邊距 16px；卡片內距 16px；底部導覽固定。 |
| 460～679px | 大手機／直向小平板 | 仍以單欄為主，可把同一張卡內的兩個次要按鈕並排。 |
| 680～1023px | 平板／小型桌機 | 內容最大寬度維持 780px；記帳設定與匯率可雙欄，主要閱讀內容不強迫雙欄。 |
| 1024px 以上 | 桌機 | 主內容置中，最大寬度 1120px；可將次要摘要放右側欄，但主要行程、預訂、待辦、記帳清單仍保留清楚的直向閱讀順序。 |

避免只以單一「手機／桌機」斷點處理。現有 460px、680px、820px 規則可整理成上表的語意：小手機修正、平板展開、PDF 等較寬內容的特殊處理。

## 7. 桌機相容策略

桌機不是另一套設計，而是手機內容有更多留白的版本：

- 手機的底部四項主導覽，在桌機可改為左側直向導覽或上方次導覽；功能名稱、順序與選取狀態必須相同。
- 手機的「下一個行程／下一個預訂」焦點卡，在桌機可與天氣或摘要並排，但不可改變其優先順序。
- 寬螢幕可讓預訂圖片放在右側、記帳設定雙欄、統計卡並排；表單、時間軸及待辦清單仍以一欄閱讀為主。
- 所有功能皆使用同一份資料與元件，不製作只在桌機存在、手機找不到的功能。

## 8. 無障礙與旅行情境

- 所有可點擊區域至少 44 × 44px；勾選框至少 24 × 24px，四周保留可點擊空間。
- 保持文字與背景至少 4.5:1 對比；墨綠文字不可直接放在深色或照片上。若有照片，文字放在不透明或半透明的底板上。
- 選取、完成、錯誤不能只靠顏色，必須同時有文字、圖示、勾選或狀態標籤。
- 按鈕與圖示需有清楚的中文 `aria-label`；只有圖示的操作必須提供工具提示。
- 固定頂部與底部列須避開 iPhone 安全區，內容底部需保留至少「底部導覽高度 + 安全區」的空間，不能被遮住。
- 長行程名稱、地址、訂位代碼必須能換行或以省略號呈現，不能撐破卡片。
- 網路不穩時，保留已載入的行程與票券摘要；雲端同步、天氣更新失敗要顯示可理解的提示與重試方式，不能讓主要行程消失。

## 9. 驗收標準

### 手機基本操作

- 在 320px、375px、390px、414px 寬度下，沒有橫向捲動、文字重疊、按鈕被底部列遮住或卡片內容溢出。
- 使用者可在三次點擊內完成：查看下一個行程、開啟下一張票券、新增一筆支出、勾選一個待辦。
- 底部主導覽只顯示行程、預訂、待辦、記帳與中央新增；PDF 預覽可從更多工具進入。
- 行程、預訂、待辦、記帳的第一屏皆能看見該頁最重要的摘要與下一步操作。

### 一致性與視覺

- 四個主頁使用同一組顏色、8px 倍數間距、12px 卡片圓角與一致陰影。
- 每個頁面同一時間最多一個填滿色的主要按鈕；刪除等危險操作不放在容易誤觸的位置。
- 預訂卡在手機上為單欄，圖片有則為 16:9 橫幅；待辦清單不再以桌面表格方式擠壓。

### 無障礙與桌機

- 所有主要操作可用鍵盤 Tab 看見焦點，焦點樣式清楚可見。
- 螢幕閱讀器能讀出每個圖示按鈕的用途、目前選擇的頁面與待辦完成狀態。
- 680px、820px、1024px 寬度下，資料不遺失、操作名稱不變；桌機的雙欄僅增加空間，不改變功能位置邏輯。

### 實作前後檢查

- 修改前先建立 `codex/mobile-first-ui` 分支或完成一次可回退的 commit。
- 修改後需以瀏覽器實際截圖檢查至少 390px 手機、768px 平板、1280px 桌機三種寬度，並檢查瀏覽器 console 沒有新增錯誤。
- 保留一份原本 CSS 的 git commit，確認可以用正常 revert 回到目前版面。

## 10. 不包含項目

- 不改動既有旅程、預訂、待辦、記帳、共享、雲端同步或 PDF 匯出的資料結構與商業規則。
- 不新增地圖導航、離線地圖、付款串接、推播通知或新的第三方服務。
- 不重新繪製品牌 Logo，也不大量加入裝飾插畫；旅行感以色彩、留白、卡片與少量圖示維持。
- 不在本階段移除既有 PDF 預覽功能，只調整它在手機導覽中的入口位置。

## 11. 風險與可回退方案

| 風險 | 為什麼要注意 | 安全做法與回退 |
| --- | --- | --- |
| 固定底部列遮住內容 | iPhone 安全區、不同瀏覽器高度會不同 | 統一使用 `env(safe-area-inset-bottom)` 與內容底部留白；每次截圖檢查；若出錯可先回退導覽相關 CSS。 |
| 調整頁籤導致功能找不到 | 現有 PDF 預覽與新增按鈕已有使用習慣 | 先保留所有功能與事件名稱，只改位置；加入更多入口後再做人工 smoke test。 |
| 大量 CSS 覆寫造成桌機壞掉 | 現有樣式已累積多個窄版規則 | 以 token 與元件區塊逐步替換；每完成一頁就測手機、平板、桌機並 commit。 |
| 票券、地址、姓名太長 | 真實旅行資料常比示意圖長 | 對長字串做換行／省略處理；用長中英文地址、長訂位代碼驗證。 |
| 誤觸刪除或新增 | 旅行途中注意力有限 | 危險操作放詳細頁更多選單，刪除前要求確認；主要新增入口明確且可取消。 |

## 12. 規格自我檢查

- 本規格沒有未決 TODO；「更多」可採既有按鈕開啟的選單或對話框，實作時選擇與現有元件最一致的方式即可。
- 所有提案都以現有行程、預訂、待辦、記帳與 PDF 預覽結構為基礎，沒有要求資料遷移。
- 「中央＋」會依目前頁面開啟對應的既有新增表單；若使用者位於 PDF 或更多工具頁，則顯示可選擇新增項目的選單，避免猜測。
